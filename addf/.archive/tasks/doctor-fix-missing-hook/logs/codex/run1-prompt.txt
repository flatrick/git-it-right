## The defect

`gir doctor --fix` fixes the "exec-bit" check: tracked files with mode 100644 whose path ends in `.sh` or starts with `.githooks/` should become 100755 in the index. The fix is `Fix::Chmod` in `src/cmd/doctor.rs`, applied in `fn apply`, which runs `git update-index --chmod=+x -- <paths>`.

That command needs each file in the working tree and re-reads it, which causes two bugs:
1. If a flagged file was deleted from the working tree, git fails with `fatal: Unable to process path ...`, and `gir doctor --fix` exits 2 part-way, after applying earlier fixes and before later ones.
2. If a flagged file has an unstaged local edit, `--fix` stages that edit.

It must keep working for files outside a sparse checkout's cone (skip-worktree entries without files): today those work, and they must stay skip-worktree.

## Required design (do not choose another)

- When `index_checks` flags a path for exec-bit, also keep its object ID and whether it is skip-worktree. Read the index with `git ls-files -s -v -z` (the `-v` adds a one-letter tag before each record; `S` means skip-worktree) instead of the current `git ls-files -s -z`, and keep all other behavior of `index_checks` the same.
- Change `Fix::Chmod` to hold, per path: the path bytes, the object ID, and the skip-worktree flag.
- In `apply`, write one record per path to `git update-index -z --index-info` on stdin: the bytes `100755 <object>\t<path>\0`. Then, if any path was skip-worktree, write those paths, each followed by `\0`, to `git update-index -z --skip-worktree --stdin` on stdin.
- Pass paths only on stdin, never as command-line arguments. Use the existing helpers in `src/git.rs` (for example `run_raw`, `run_with_stdin`, or a small byte-input variant next to them if needed); keep their style.
- Paths are bytes (`Vec<u8>`) throughout `doctor.rs`; keep using `display_path` for report text. The report line must not change.
